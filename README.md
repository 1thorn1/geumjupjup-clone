# 금줍줍 모작

리워드 앱 **금줍줍**의 핵심 흐름(채굴 → 광고 보고 금 줍기 → 상품 교환)을 Expo(React Native)로 따라 만든 과제입니다.
오퍼월(오퍼 리스트 → 상세 → 참여 → 지급)과 지갑은 **Supabase(PostgreSQL + REST API)** 서버와 연동하고, 광고·결제 SDK는 mock으로 대신합니다.

- 분석 문서: [docs/analysis.md](docs/analysis.md) (실제 앱을 써 보고 정리한 화면·흐름)
- **API·DB 설계: [docs/api-db.md](docs/api-db.md)** (요구사항, REST API 명세, ERD·테이블, 데이터 보호)
- 설계 문서: [docs/design.md](docs/design.md) (폴더 구조, 상태 관리 방식, 더미 데이터 구조)
- DB 스키마: [supabase/migrations](supabase/migrations) (테이블, RLS, 서버 함수, 기본 데이터)
- 버그 리포트: [docs/bug-report.md](docs/bug-report.md) (실제 앱을 쓰며 발견한 문제)

## 실행 방법

### 1. APK 설치 (안드로이드)
- 설치 페이지 (QR 코드): https://expo.dev/accounts/ddabongnyang2/projects/geumjupjup-clone/builds/710e1209-eb06-413d-879f-8f86dadefd41
- APK 파일 직접 받기: https://expo.dev/artifacts/eas/c1-87TYkdrbupmL13I33RXfR4fdPjVbUZVg6xwoC8C0.apk
- 안드로이드 휴대폰에서 링크를 열거나 QR 코드를 찍어 설치합니다. "출처를 알 수 없는 앱" 설치 허용이 필요할 수 있습니다.
- 클라우드 Supabase 서버에 연결된 빌드라 인터넷 연결이 필요합니다. 처음 실행하면 기기별 익명 사용자가 만들어지고 샘플 금 내역이 지급됩니다.

### 2. 소스에서 실행
Node.js(LTS)와 서버(Supabase)가 필요합니다.

**서버 준비 (둘 중 하나)**
- 로컬: Docker가 켜져 있으면 `npx supabase start` 한 번으로 DB·인증·REST API가 뜨고 스키마가 적용됩니다.
- 클라우드: Supabase 프로젝트를 만들고 `npx supabase link` → `npx supabase db push`로 스키마를 올립니다. 대시보드의 Authentication 설정에서 **익명 로그인(Anonymous sign-ins)**을 켭니다.

**앱 설정**: 프로젝트 루트에 `.env.local`을 만들고 서버 주소와 공개 키를 넣습니다.
```bash
EXPO_PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...
```

```bash
npm install
npx expo start
```

- **웹**: 터미널에서 `w`를 누르면 브라우저에서 열립니다. 개발자 도구의 모바일 화면 크기로 보는 것을 권장합니다.
- **휴대폰 (Expo Go)**: [Expo Go](https://expo.dev/go) 앱으로 터미널의 QR 코드를 찍습니다. (Expo SDK 58)

### 3. APK 직접 빌드
```bash
npx eas-cli build -p android --profile preview
```
`eas.json`의 `preview` 프로필이 바로 설치 가능한 APK로 빌드합니다. Expo 계정 로그인과, EAS 환경 변수(`preview`)에 위 두 값(클라우드 Supabase 주소·공개 키)이 필요합니다.

### 개발자 모드 (시연용)
홈 왼쪽 위 **금줍줍 로고를 20번** 누르면 열립니다.
채굴만으로는 상품 교환까지 금을 모으기 어려워서, 테스트와 시연을 위해 만들었습니다.

- 보유 금 추가 / 0으로 만들기
- 채굴 속도 올리기 / 개발자 가속 제거
- 채굴량을 바로 상한까지 채우기
- 출석·룰렛 오늘 기록 초기화, 처음 설치한 상태로 초기화

잔액을 직접 바꾸지 않고 서버에 "개발자 모드" 내역을 추가하는 방식이라, 개발자 모드를 써도 **잔액 = 내역의 합** 원칙이 유지됩니다.

## 핵심 흐름

```
금이 시간에 따라 자동으로 채굴됨 (상한에 차면 멈춤)
  → [광고 보고 금 줍기] → 쌓인 채굴량이 지갑에 적립 → 채굴은 0부터 다시
  → 선물 탭에서 상품 교환 → 잔액 차감

출석·룰렛 보상 = "채굴 속도(%)" 증가
오퍼월 미션 보상 = 금 + 채굴 속도 (단계 완료 → 3초 뒤 서버가 지급)
```

실제 앱의 미션 보상은 채굴 속도지만, 과제의 오퍼월 요구사항(지급 후 잔액 갱신)에 맞춰 오퍼 단계마다 금과 속도를 함께 지급합니다.

## 기술 선택 이유

| 기술 | 이유 |
|---|---|
| **React Native** | 앱을 새로 만들면서 Swift·Kotlin 같은 새 언어까지 처음부터 배우기보다, 조금이라도 익숙한 React와 TypeScript로 구현하는 것이 과제 기간 안에 완성도를 높이는 방법이라고 판단했습니다. 하나의 코드로 안드로이드·iOS·웹을 함께 실행할 수 있다는 점도 고려했습니다. |
| **Expo (SDK 58) + TypeScript** | 네이티브 설정 없이 웹·Expo Go·APK로 바로 실행할 수 있어 과제 기간 안에 화면 구현에 집중할 수 있었습니다. 금 단위·내역 타입을 TypeScript로 고정해 실수를 컴파일 단계에서 잡았습니다. |
| **Expo Router** | 파일 하나가 화면 하나라서 화면 구조가 폴더로 보입니다. 탭(홈/만보기/선물/프로필)과 스택(광고, 내역, 오퍼월 상세 등)을 레이아웃 파일로 나눴고, 오퍼월 상세는 동적 경로(`offer/[id]`)로 만들었습니다. |
| **React Context + useReducer** | 잔액·채굴 상태는 여러 화면이 함께 써서 한 곳에 둬야 합니다. 상태 종류가 지갑·채굴·오퍼월 세 가지로 적어서 외부 라이브러리(Redux, Zustand) 없이 React 기본 기능으로 충분하다고 판단했습니다. 지갑 규칙(중복 방지, 잔액 부족)은 reducer 한 곳에 모았습니다. |
| **Supabase** | 오퍼 구조와 금 내역을 실제 DB 테이블로 설계하고 REST API로 연동하기 위해 썼습니다. PostgreSQL이라 ERD를 그대로 테이블·외래 키·유니크 제약으로 옮길 수 있고, 조회 API가 자동으로 생겨 짧은 기간에 서버를 갖출 수 있었습니다. 규칙이 필요한 쓰기(참여, 단계 완료, 지급, 교환)는 DB 함수로 만들어 트랜잭션·잠금·멱등성을 DB가 보장하게 했습니다. Firebase는 문서형 DB라 관계형 ERD와 맞지 않았고, 서버를 직접 만들기에는 기간이 부족했습니다. |
| **AsyncStorage** | 기기에만 필요한 값(채굴 시작 시각, 로그인 세션)을 저장합니다. |
| **react-native-reanimated** | 룰렛 회전, 출석 도장, 보상 팝업 같은 연출을 UI 스레드에서 부드럽게 돌리기 위해 썼습니다. |

### 설계에서 신경 쓴 점
- **잔액 = 내역의 합**: 잔액을 따로 저장하지 않고 항상 내역에서 계산합니다. 잔액과 내역이 어긋날 수 있는 구조 자체를 없앴습니다.
- **금은 정수로 저장**: 0.000000000001g(10⁻¹²g)을 1로 보는 정수로 저장해 소수 계산 오차를 막았습니다.
- **중복 방지는 key로**: 모든 적립·보상에 고유 key(`mining:시작시각`, `attendance:날짜` 등)를 붙이고, 같은 key는 다시 처리하지 않습니다. 서버에서는 이 key가 멱등성 키가 되어 DB 유니크 제약으로 지켜집니다. 버튼 연타·재전송에도 보상은 한 번만 들어갑니다.
- **앱은 DB를 직접 고치지 못함**: 모든 테이블에 RLS를 켜고 쓰기는 서버 함수로만 합니다. 잔액 검사·가격 확인·지급은 서버가 합니다.
- **낙관적 업데이트**: 금 줍기와 교환은 잔액을 먼저 바꾸고, 서버가 실패하면 그 key의 내역을 지워 되돌립니다. 잔액이 내역의 합이라 롤백은 "내역 한 줄 삭제"로 끝납니다.
- **저장 대신 계산**: 채굴량(시작 시각 + 경과 시간), 채굴 속도(기본 100% + 받은 보상), 출석 여부, 룰렛 남은 횟수는 저장하지 않고 기록에서 계산합니다.

자세한 내용은 [API·DB 설계](docs/api-db.md)와 [설계 문서](docs/design.md)에 있습니다.

## 실제 앱과 다르게 한 부분
- **행운추첨 → 룰렛**: 실제 앱은 회차제 추첨이라 개표 시각까지 기다려야 결과가 나옵니다. 시연이 어려워 광고 보고 돌리면 바로 결과가 나오는 룰렛으로 단순화했습니다.
- **오퍼월 보상**: 실제 앱은 채굴 속도만 주지만, 과제 요구사항(잔액 갱신)에 맞춰 금과 속도를 함께 지급합니다.
- **오퍼 단계 완료**: 실제로는 광고주가 설치·가입을 확인해 주지만, mock이라 버튼으로 완료 처리합니다.
- **이미지**: 캐릭터·금괴·브랜드 이미지는 저작권과 상표 때문에 이모지와 아이콘으로 대신했습니다.
- **채굴 속도**: 시연하기 쉽도록 기본 속도에서 1분이면 상한까지 차게 했습니다.

## 폴더 구조

```
src/
├─ app/        화면 경로 (Expo Router). 파일 하나 = 화면 하나
├─ api/        서버 호출 (설계한 REST API 하나 = 함수 하나)
├─ lib/        Supabase 클라이언트
├─ features/   기능별 코드 (wallet, mining, ads, attendance, roulette, exchange, history, offer, ...)
├─ data/       화면용 고정 데이터 (미션 타일, 상품 카드, 보상 수치)
└─ utils/      날짜 등 공용 함수
supabase/      DB 스키마 (migrations), 로컬 서버 설정
docs/          분석 문서, API·DB 설계, 설계 문서, 버그 리포트
```
